# 테러 빅데이터 예측 시뮬레이션 — 프로토타입

Global Terrorism Database(GTD) 15만여 건으로 만든 **예측 시뮬레이션 프로토타입**입니다. 최종 구상의 전제인 "사건의 성격이 위치로부터 예측 가능한가"를 검증하는 데까지 진행했습니다.

> 북경이공대학교 빅데이터 수업 프로젝트 · 개인 작업 · 2026-04

---

## 구상한 것

과제는 "테러 빅데이터로 예측 시뮬레이션을 만들 것"이었습니다. 제가 그린 완성형은 이렇습니다.

경찰 기록, 군사 동향, 테러 단체별 활동 이력 같은 **여러 출처의 데이터를 결합**하면, 단순히 과거 통계를 보여주는 걸 넘어 **특정 테러 단체의 다음 목표 지점이나 공격 수법을 예측**하는 시뮬레이션을 만들 수 있습니다. 인프라와 데이터가 충분히 받쳐준다면 여기서 더 나아가, 같은 방식으로 **국가 단위의 군사 움직임과 동향을 읽어내는 쪽**으로도 확장할 수 있다고 봤습니다.

## 실제로 만든 것

수업 실습 범위 안에서 쓸 수 있었던 데이터는 GTD 하나뿐이었고, 결과적으로 **그 구상이 성립하기 위한 최소 전제를 확인하는 단계**까지 갔습니다.

전제는 이겁니다 — **테러 사건의 성격이 애초에 위치로부터 예측 가능한가?** 이게 안 되면 다중 출처를 붙이고 인프라를 키워도 예측 시뮬레이션은 성립하지 않습니다.

그래서 다른 정보를 일절 주지 않고 **위도·경도 두 개만으로 그 사건에 쓰인 무기 유형을 맞히는** 모델을 만들어 봤습니다.

| | |
|---|---|
| 구상한 최종 형태 | 다중 데이터 결합 → 단체별 다음 목표·수법 예측 → 국가 군사 동향 분석 |
| 검증한 전제 | 위치만으로 사건의 성격을 예측할 수 있는가 |
| 실제 결과물 | 좌표 → 무기 유형 4종 분류 KNN · 테스트 정확도 68.0% |
| 하지 못한 것 | 다중 데이터 결합, 단체별 예측, 시계열, 모델 튜닝 |

결론부터 말하면 **전제는 부분적으로 성립합니다.** 좌표만으로도 찍기보다 유의미하게 나은 예측이 되지만, 그 폭은 생각보다 작았습니다. 아래 결과 항목에 그대로 적었습니다.

## 데이터

[Global Terrorism Database](https://www.start.umd.edu/gtd/) — 1970~2015년 전 세계 테러 사건 기록.

- 원본 100개 이상 컬럼 중 23개로 줄인 파일에서 **11개 컬럼만 선별** 로드 (152,252건)
- 무기 유형이 명확한 4종만 남겨 **130,681건**으로 축소

분포는 상당히 치우쳐 있고, 이게 결과 해석의 핵심입니다.

| 무기 유형 | 건수 | 비율 |
|---|---:|---:|
| Explosives/Bombs/Dynamite | 77,755 | 59.5% |
| Firearms | 49,801 | 38.1% |
| Melee | 2,922 | 2.2% |
| Chemical | 203 | 0.2% |

## 분석 흐름

**1. 전처리 · 탐색** — [`data_preprocessing.ipynb`](data_preprocessing.ipynb)

- 필요한 컬럼만 로드, `describe()`로 분포 확인, 수치형 컬럼 상관관계 히트맵
- 무기 유형 4종으로 필터링 → 연도별 / 공격유형별 / 무기유형별 집계
- 정제 결과를 `arms_DF_ver2.csv`로 저장

**2. 모델링** — [`knn.ipynb`](knn.ipynb)

- 입력: **위도·경도 2개만**. `country`나 `region`을 넣으면 이미 위치가 인코딩된 값으로 점수를 버는 셈이라 일부러 제외했습니다
- 정답: 무기 유형 4종 (Chemical=0, Explosives=1, Firearms=2, Melee=3)
- 8:2 분할(`random_state=20`) → 학습 104,544건 / 테스트 26,137건
- `KNeighborsClassifier` 기본 설정(k=5)
- 무기 유형별 좌표를 색으로 구분한 산점도로 지리적 분포 시각화

KNN을 고른 건 질문 자체가 지리적이기 때문입니다. "주변에서 무슨 일이 있었는지 보고 판단한다"는 KNN의 동작 방식이 이 문제의 구조와 그대로 맞습니다.

## 결과

| | 정확도 |
|---|---:|
| 학습 데이터 | 73.3% |
| **테스트 데이터** | **68.0%** |
| 참고: 전부 다수 클래스로 찍었을 때 | 59.5% |

**68%만 보면 그럴듯하지만, 다수 클래스(폭발물)로 전부 찍어도 59.5%가 나옵니다.** 좌표가 실제로 기여한 건 **약 8.5%p**입니다.

전제 검증이라는 관점에서 이 숫자를 읽으면 이렇습니다.

- 위치에 신호가 **있긴 있다** — 무작위나 다수결 찍기보다 확실히 낫고, 산점도에서도 무기 유형이 지역별로 뚜렷하게 뭉쳐 있는 게 보입니다
- 다만 **좌표 두 개만으로는 부족하다** — 8.5%p라는 폭은 실용 시뮬레이션의 근거로 삼기엔 얇습니다. 구상했던 다중 데이터 결합(단체 이력, 시기, 대상 유형 등)이 왜 필요한지를 역으로 보여주는 결과이기도 합니다

예시로 필리핀 루손섬 부근 좌표(15.675, 120.332)를 넣으면 `Firearms`로 예측합니다.

## 한계

정리하면서 확인한, 지금 상태의 명확한 약점들입니다.

- **평가 지표가 정확도 하나뿐** — 클래스 불균형이 심한 데이터에서 정확도만 보면 판단을 그르칩니다. 클래스별 precision/recall이나 혼동 행렬을 봤어야 했습니다. 특히 화학무기(203건, 0.2%)는 모델이 사실상 한 번도 맞히지 못했을 가능성이 큽니다
- **레이블을 위치로 부여함** — 정렬 후 `[0]*203 + [1]*77755 + ...` 형태로 정답을 만들었습니다. 정렬 순서와 개수가 정확히 맞아떨어져야만 성립하고, 어긋나도 에러 없이 조용히 틀립니다
- **좌표 스케일링 없음** — KNN은 거리 기반인데 위도(-90~90)와 경도(-180~180)의 범위가 달라 경도가 더 세게 작용합니다
- **하이퍼파라미터 미조정** — k값 탐색이나 교차검증을 하지 않았습니다
- **데이터 구조상의 근본 한계** — GTD는 "발생한 사건"만 담고 있습니다. 발생하지 않은 사례가 없으니, 이 데이터만으로는 "여기서 테러가 일어날까"를 학습시킬 수 없습니다. 구상한 예측 시뮬레이션으로 가려면 데이터 출처를 늘리는 것 이전에 이 문제부터 풀어야 합니다
